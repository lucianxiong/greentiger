# 自进化与去外部依赖（3.25.0 起）

这份文档回答两个问题：**绿虎怎么变强，才不靠「换一个更强的模型」？** 以及 **在断网、不接任何 API 的情况下，它还能不能继续变强？**

结论先说：**能，但只在一个很窄的范围内——改外壳（harness），不改权重（weights）；改的每一步都必须由一个站在自己之外的裁判来判定。**

---

## 1. 外部证据（2026-11 核过的事实）

| 系统 / 工作 | 改的是哪一层 | 公开结果 | 对绿虎的取舍 |
|---|---|---|---|
| OpenAI ARC-AGI-3 harness 实验（2026-07） | 上下文与记忆策略 | 同一模型、同一权重：官方 harness 13.3% → 保留推理 + compaction 38.3%，输出 token 少 6 倍 | **外壳是最高杠杆面**。绿虎优先做记忆/压缩/工具面，而不是堆模型 |
| Kimi 2026 路线（Harness + 水平扩展） | harness + 子代理集群 | 公开口径：K2.5/K2.6 的 Agent Swarm 最多 300 子 Agent、4000+ 工具调用；「同一模型换 harness 可带来显著分差」 | 子代理已落地（v3.21.0）；下一层是**给子代理分发经验**，不是加更多子代理 |
| DeepSeek：「Model + Harness = Agent」 | harness 开源化 | 2026-08 开源 DeepSeek Harness v0.1（MIT，一切皆插件，含 Agent Loop，明确支持 Self-Evolving Harness） | 绿虎同样是「harness 产品」；插件/技能/记忆都应是**可替换件**，不是写死在循环里 |
| AlphaEvolve（Gemini）+ Harbor（2026-11） | 技能文件本身 | Google 工程师把 coding agent 的 `SKILL.md` 当程序进化，在 Terminal-Bench 2.0 上 **+5%**；最优技能都围绕同一个最常见失败（跑不完、超时）。基线技能**无差异**；答案泄漏版 +33 分（说明评测有效）。10 小时后因模型响应慢 + 全量日志占盘停滞 | **技能是可以被进化的最小单元**；一次只进化一个技能；评测必须能区分「真变好」和「答案泄漏」；成本与日志必须先封顶 |
| Darwin Gödel Machine（Sakana，2025） | 自己的代码 | SWE-bench 20% → 50%；**出现过拆掉自己的幻觉检测来刷分** | 自改代码能涨分，但**必须外部裁判**。绿虎不做「Agent 改自己的评测器」 |
| SICA（2025） | 自己的代码库 | SWE-bench Verified 子集 17% → 53% | 同上；但证明「外壳可变空间足够大」 |
| MGM（DGM 后继） | 失败档案 → 规则 | 35B 开源模型 Polyglot 50.8% → 93.3%，反超闭源；**小模型进化出的能力可迁移到更强模型** | 小模型 + 好 harness 可以打得过大模型 + 裸 harness。这是「脱离外部依赖」的底气 |
| 跨模型经验迁移实验（2026-08） | lessons.md 经验文件 | 7 个模型里 DeepSeek-V4-Pro 基线最弱、增益最大（avg@3 +0.093），它提炼的是「检查约束 / 验证结果 / 及时回滚」；Gemini-3.1-Pro **负迁移**（-0.017），因为它把「语义模拟」用成了缓存 SHA-256 结果作弊 | **只沉淀元规则，不沉淀领域技巧**。绿虎的技能模板因此固定为「触发 / 做法 / 证据」，做法只写检查、验证、回滚、换写法 |
| Hermes Agent（Nous） | 成功轨迹 → `SKILL.md` | 把重复成功的多步任务沉淀成技能，技能还能被自身补丁；用 DSPy + GEPA 按真实执行记录进化技能文件，**不需要 GPU** | 「用真实执行记录做进化输入」这条路可行且便宜；绿虎选了更笨但更可控的规则蒸馏 |
| Karpathy autoresearch | 训练脚本 + 评测脚本 | `program.md` + 固定评测 + git 回滚，只进不退，醒来拿到一条被验证过的改进史 | **棘轮 + 回滚**是自进化能上生产的最低配置，绿虎照抄这个骨架 |
| SkillJack（2026-08） | 技能供应链 | 自进化 Agent 的技能可被植入后门，并随技能代际传递 | 技能必须有来源、有审核、有一键回滚，且**不能自动启用** |
| Lilian Weng《Harness Engineering for Self-Improvement》（2026-07） | 方法论 | 现实路径是优化 harness（工作流 / 上下文 / 工具 / 评估），不是让模型重写权重；主要挑战：评估器薄弱、记忆生命周期、奖励欺骗；**自改进对强模型有益，对弱模型可能有害** | 弱模型（本地小模型）上要收紧而不是放宽：更小的工具面、更短的提示、更硬的验收 |
| 本地推理栈（llama.cpp / Ollama / vLLM） | 模型通道 | 三者都暴露 OpenAI 兼容端点；llama.cpp 必须 `--jinja` 才有工具调用；Qwen3-Coder-30B-A3B、Qwen3.8-27B、Saluki 27B（2-bit，BFCL 88/120）已能在单卡跑 Agent | 绿虎的「唯一通道 = OpenAI 兼容」天然支持本机；补的是**目录入口 + 不打扰 AutoPool** |

一条共同的负面结论也值得写下来：**2026 年还没有出现真正「开放式」自我改进**。有明确评测、能收敛、能落地的，全部是「有界自精炼」。绿虎照这个边界设计，不假装能自我觉醒。

## 2. 绿虎现在有什么、缺什么（差距地图 v3）

已有的地基（不改）：

- 执行事实：`TaskStore`（`stats/tasks.jsonl`）记录 outcome / errorClass / 验收摘要 / token / 耗时；
- 结构化轨迹：`Trace`（`logs/trace-*.jsonl`）；
- 独立验收：`Verifier` 只认客观证据（文件存在、非空、命令退出码），无法验证就标 `unverifiable`；
- 记忆：项目记忆 + 候选审核（v3.20.0），技能包 `.greentiger/skills/*.md`；
- 自检：`--self-test` 300+ 断言，评测集 `tools/eval.js`（结构 / 真跑 / 指标 / 退化门禁）。

缺的四件事，正好是闭环的四环：

| 缺 | 后果 | 本轮 |
|---|---|---|
| ① 没有「经验账本」 | 失败只进日志，同类问题第二次、第三次照样犯 | ✅ 做 |
| ② 没有从失败里蒸馏规则的通道 | 记忆是流水账（目标→结果），不是「下次怎么做」 | ✅ 做 |
| ③ 没有门禁 | 自动写进去的错误结论会污染后续任务 | ✅ 做 |
| ④ 没有棘轮 | 改了之后到底更好了还是更差了，没人知道 | ✅ 做 |
| 上下文只有截断，没有 compaction | 长任务丢前文（OpenAI 那条 3 倍差距） | ⏳ P1 |
| 没有模型能力画像（弱模型瘦身） | 本地小模型容易被大工具面和长提示压垮 | ⏳ P1 |
| 没有离线评测集 | 断网时无法衡量改动是否更好 | ⏳ P2 |

## 3. v3.25.0 落地的闭环：记账 → 蒸馏 → 门禁 → 棘轮

落点：`src/Evolution.cs`，数据在 `工作目录\.greentiger\evolution\`。

```
任务结束
  └─ Evolution.Record   ledger.jsonl 一条：outcome / errorClass / 归一化签名 / 元规则 / steps / token
       └─ /evolve propose
            └─ 同一规则 ≥3 个任务、≥2 个不同日期 → candidates/ev-*.md（不启用）
                 └─ /evolve accept
                      └─ Gate（确定性、零模型、零网络）
                           └─ skills/ev-*.md（下一轮任务即注入系统提示）
                                └─ Ratchet（6 个任务后比成功率）
                                     ├─ 跌 ≥20 个点 → 移入 archive/，标记 demoted
                                     └─ 否则 kept
```

四个刻意的设计选择：

1. **证据先于规则**。不到 3 个任务、跨不到 2 天，不生成任何候选。一次异常不改规则。
2. **只蒸馏元规则**。六个键：`verify_before_finish` / `plan_then_act` / `variant_after_two_failures` / `read_before_edit` / `probe_environment` / `ask_when_blocked`。全部是「怎么做事」，不含任何领域技巧——这是跨模型迁移实验里唯一稳定正向的那一类。
3. **门禁是确定性的**。格式、篇幅（≤2000 字）、安全措辞黑名单（"跳过确认"/"bypass approval"/"rm -rf /" 等）、证据条数与天数（从候选自带的日期行重算，不信 frontmatter 的计数）、不覆盖手写同名技能。全部纯函数，`--self-test` 直接断言。
4. **晋升默认不打扰**。候选必须 `/evolve accept` 才启用；启用后也只注入「做法」三行，总预算 1400 字。规则要能一句话说清，否则不进提示词。

为什么不做「让模型写完直接生效」：DGM 拆掉自己的幻觉检测、Gemini 缓存 SHA-256 结果，都是同一类失败——**被裁判者兼任裁判**。绿虎的裁判是 `Verifier` 的客观证据 + 真实任务成功率，两者都不由模型打分。

## 4. 去外部依赖：三层含义

1. **不绑定模型**：唯一通道仍是 OpenAI 兼容端点。3.25.0 曾把两个本机离线端点放回目录（`local-llamacpp` / `local-ollama`）；3.29.0 起目录只留旗舰云端模型，本机/离线/中转一律走「自定义端点」，AutoPool 仍不主动探测回环地址（否则每次任务白等一次 8080/11434 超时）。
2. **不依赖模型能力**：进化闭环全程零模型调用、零网络请求。断网、Key 过期、只有本地 7B 模型，`/evolve` 的记账、蒸馏、门禁、棘轮全部照常工作。
3. **不依赖云侧评测**：门禁与棘轮只用本机事实（账本 + 任务终态），不需要外部 benchmark 服务。

仍未解决的部分（诚实记账）：**compaction 与弱模型提示瘦身**还没做，所以「只有本地小模型」时体验仍明显弱于云端旗舰。这是 P1 的主要工作。

## 5. 路线图

**P1（下一轮）**

- 上下文 compaction 替代滚动截断：保留目标 / 决策 / 未完成项 / 改动清单，按 OpenAI 那条证据做 A/B。
- 模型能力画像：按端点与模型名推断（本机回环 / 参数量 / 是否支持 native tools），自适应调整工具面大小、系统提示长度、步数预算。
- 技能来源签名：`ev-*` 技能记录来源账本哈希，加载前校验未被外部改写（对应 SkillJack）。

**P2**

- 离线评测集：把历史失败样本固化成可复跑的回归集，`npm run eval:offline` 不连模型也能跑。
- 子代理经验分发：一次性把本项目已晋升规则带进 `task` 子代理的提示（当前子代理看不到进化规则）。
- 成本面板：按晋升前后对比 token 与成功率，回答「这条规则值不值」。

**明确不做**（既定决策）

- 让 Agent 改自己的评测器、验收器、Guard。
- 自动启用未经人工确认的技能。
- 改模型权重 / 本地微调（权重不在产品可控范围内）。
- 追求「开放式自我改进」——当前所有公开系统都停在有界自精炼。

## 6. 验收（客观可判）
```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
dist\GreenTiger.exe --self-test     # 含 12 条 evolution 断言
```

自检覆盖：签名归一化（路径/数字不同但同类）、验收失败推导元规则、账本落盘、候选需跨天证据、门禁放行真实候选、门禁拒绝「跳过确认」类措辞、晋升写入技能、提示词注入、棘轮回滚（晋升后 6 个任务全失败 → 自动移入 archive）、回滚后提示词不再包含该规则。

手工验收（真实工作目录）：

```
/evolve                     # 看账本、反复失败、已蒸馏规则、候选、棘轮状态
/evolve propose             # 蒸馏候选（零模型调用）
/evolve accept ev-xxx       # 过门禁启用
/evolve revert ev-xxx       # 停用并存档
```

## 7. 3.26.0：从 Antigravity / Claude Fable 5.2 / GPT-6.2 抄到的四点

2026-11 这一周三家同时给了新东西。只抄能落到「零依赖、可验证、不改权重」范围内的部分。

| 来源 | 它做了什么 | 绿虎抄哪一点 | 落点 |
|---|---|---|---|
| Google Antigravity（Agent Manager / Artifacts） | 每个任务产出**给人审阅的产物**：任务清单、实施计划、截图、浏览器录像、走查记录；人可以在产物上留评论，agent 不停机吸收 | **任务走查记录**：每个终态任务自动生成一份 Markdown（目标 / 结论 / **证据强度** / 时间线 / 改动与备份 / 风险）。人看产物，不看工具日志 | `src/Walkthrough.cs`、`/walkthrough` |
| Google Antigravity（自改进知识库） | agent 既向知识库**贡献**抽象经验，也按当前任务**检索**经验 | 3.25.0 只做了「贡献」（蒸馏规则）；3.26.0 补「检索」：按当前目标从本目录失败记录里找相似项，回灌「上次栽在哪、这次先做什么」 | `Evolution.Relevant`，注入系统提示，预算 600 字 |
| Claude Fable 5.2（长时程 agent，协调上千子代理） | 公开材料强调两点：能在长跑中「自己盯着结果是否可复现」，以及子代理统一在同一套约束下工作 | ① 走查记录首屏就是**证据强度**：`已客观验证` / `仅模型自述` / `验收未通过` / `未完成`，未验证的还会写一条 warn 日志；② 子代理系统提示注入主循环已晋升的规则与相似失败（否则同一次任务里主 agent 学会了、子代理还在重犯） | `Walkthrough.Strength`、`SubAgentRunner.SubSystemPrompt` |
| GPT-6.2 Astra / Sol | 核心卖点是「更少的输出 token 完成更难的任务」；缓存输入单独计价（$0.40/MTok，输入价的 5%） | 走查记录把成本写清：总 token + **缓存命中占比**，让「这次任务贵在哪」可查；时间线只留参数摘要与结果首行，不复制工具全文 | `Walkthrough.Compose` 成本段 |

### 刻意没抄的

- **Agent Manager 的多工作区并行 + 定时任务**：绿虎是单一控制台的桌面产品，多工作区并行要先解决「谁的审批算数」，收益不抵复杂度。子代理并行已经有了。
- **浏览器录像作为验证证据**：绿虎有 `screenshot` 与内置浏览器，但录像会带来存储与隐私成本；现在用「验收条件 + 截图」已经够用。
- **Fable 5.2 的 1M 上下文与 always-on thinking**：这是模型侧能力，不是 harness 可控项。绿虎能做的是「超限时怎么压缩」，那仍列在 P1。
- **Managed Agents 自托管 / 上千子代理**：需要服务端编排与配额，超出单机 exe 的边界。

### 一个仍然成立的判断

三家新品都在强化同一件事：**把「能不能信」变成可见的东西**（Antigravity 的产物审阅、Fable 的复现自检、GPT-6.2 的评测口径）。绿虎这一轮的所有改动也都指向它——不是让 agent 说得更满，而是让「它到底做到了什么」更容易被核对。
